# `/retro`

Review the completed feature workflow, changed files, test output, QA report, and unresolved decisions.

1. Show each lesson and classify it as project-specific or generalizable.
2. Wait for approval of the classification.
3. Apply project-specific lessons to the local rules when appropriate.
4. For a generalizable lesson, prepare a separate reviewed PR against the Bootstrap marketplace template. Do not silently change the shared template.

The teaching example is a state-changing endpoint whose repeat request was not specified. Propagate a rule only after explaining why that gap can recur in other .NET API projects.
