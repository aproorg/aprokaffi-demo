# Phase 5 — Orchestration and retrospective

Start from the completed phase 4 snapshot.

Build a skill that orchestrates ticket intake, planning, implementation, and testing agents. Add the retrospective step at the end of the full workflow.

## How this was generated

This was generated by prompting, from [phase 4](../phase-4/README.md):

> I want you to create an orchestration skill that's called "feature-orchestrator". It
> should contain these following steps to fully implement a feature:
>
> 1. I should get the input jira ticket it needs to implement a feature.
> 2. It should spawn a feature planner subagent, that takes the information from the ticket
>    and analyses the feature and comes up with a plan on how this feature should be
>    implemented. one plan for feature implementation and one plan for how to test the new
>    feature. It should run on opus so it can reason about the code and how best to execute
>    the implementation. It should return that plan back to the orchestration skill.
> 3. With the plan for implementation you should invoke a new subagent running on hiku
>    (since the plan should be extensive enough for the subagent to "blindly follow" the
>    plan). The sub agent should call a feature implementation skill with the plan
>    information from the orchestrator
>    1. the new feature implementation skill should only focus on implementing the service
>       layer and the web layer and not do any tests. it should fully implement the plan
>       handed down from the calling subagent
> 4. With the plan for the tests you should invoke a new subagent that's running hiku (for
>    the same reasons as above). this sub agent should invoke a new test-implementation
>    skill with information from the orchestrator
>    1. This new test-implementation skill should be specialized on analysing code coverage
>       and edge cases and wire and run tests to fully cover the implementation from the
>       plan provided by the calling sub agent
> 5. run a new Verification-agent that goes over the implementation of steps 3 and 4 and
>    makes sure that the resulting code is up to standard, following the OWASP top 10 rules
>    and the DRY principle
> 6. Run a new RETRO sub agent. the job of this retro agent is to go over this new
>    orchestration workflow run and analyse what went well and what didn't go well. find the
>    root causes of what went wrong and suggest improvements on these workflow files
>    (including the retro agent itself)
